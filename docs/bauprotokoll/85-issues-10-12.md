# 85 – Issues #10 und #12: Julia im Gespräch, Fehler auf der Owner-Seite

## #10 „Gespräch klappt nd“: Man sagt „Julia“, aber es kommt keine Antwort
Ohne echten Sprachkanal lässt sich das nicht nachstellen. Im Code gab es zwei Stellen, an denen Julia **still** blieb:

1. **Spracherkennung läuft nicht.**
   - Beispiel: In der `.env` fehlt `COMPOSE_PROFILES=tts,stt`.
   - Julia trat bei, hörte zu, bekam aber keinen Text. Der Fehler landete nur im Log.
   - **Jetzt:**
     - `/julia gespraech start` prüft die Spracherkennung **vorher** (lokal per `/health`, bei OpenAI den Schlüssel). Fehlt sie, kommt die Meldung, wie man es löst.
     - Fällt sie während des Gesprächs aus, schreibt Julia das in den Textkanal, höchstens alle 2 Minuten.
2. **„Julia“ … Pause … Frage.**
   - So spricht man natürlich, es entstehen aber zwei Sätze. Der zweite hatte kein Weckwort und wurde ignoriert.
   - **Jetzt:** Sagt man nur „Julia“, antwortet sie „Ja?“, und der nächste Satz dieser Person (innerhalb von 12 s) gilt als Frage.

Die Rechte (Verbinden/Sprechen, Sprachstatus-Intent) waren schon geprüft bzw. vorhanden.

## #12 „Uncaught TypeError: Error in input stream“ auf der Owner-Seite
- **Die CSP-Meldung „eval blockiert“ ist harmlos.** Eine Bibliothek (zod) prüft beim Laden nur, ob eval erlaubt ist, und kommt ohne aus.
- **„Error in input stream“** wirft Firefox, wenn eine Seiten-Aktualisierung unterwegs abbricht.
  - Das Dashboard lädt jede Sekunde neu.
  - Die Owner-Seite hat dabei jedes Mal die Rollen frisch bei Discord geholt. Das war langsam und lief in Discord-Limits, und hinter dem Proxy brachen Antworten ab.
- **Jetzt:**
  - Die Owner-Seite merkt sich die Rollen 3 s. Nach einer Änderung wird sofort frisch geladen.
  - `LiveRefresh` fängt abgebrochene Aktualisierungen ab, statt sie als Fehler zu melden, und macht dann 10 s Pause.
